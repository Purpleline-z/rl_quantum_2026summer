# GPU / user tasks left by the selection-htr branch

All CPU experiments used frozen SimCLR features and the MLP head. Not run, and needing a GPU (or the user):

1. **Longer schedule + Laplacian term in the end-to-end model.** The best learner found here is `lap3_k10_st4` = `aw8_all` + Laplacian regulariser (λ = 3, k = 10 graph of unlabelled images) trained with 4× the repository's head steps. In the end-to-end fine-tuned model (Task 3c recipe, `Experiment.train`) add (i) the reference-anchor weight 8 (see `new_directions` GPU task 1), (ii) the Laplacian term on a kNN graph built from the frozen initial encoder (node rules in `nd_graph_learner.GraphData`), (iii) a schedule sweep (steps ×1/×2/×4, lr ×0.5/×1). Compare with and without the graph term on identical label sets, with the shuffled-graph control, and report HTR separately (HTR accuracy and log-loss gains were the largest effects here).
2. **Schedule per budget.** Steps ×4 was chosen on 20 development seeds from {×0.5, ×2, ×3, ×4, (×6, ×8 on fewer seeds)}; a finer per-budget schedule (budget-dependent steps and learning rate, early stopping on the validation groups) and weight averaging (SWA/EMA) are unexplored and cheap on GPU.
3. **HTR data.** HTR has 26 of 144 reference images and ≈ 10 held-out decisive judgments per split. The HTR-directed selector (`vopt_htr4`) improved HTR log-loss by ≈ +0.02 (both confirmations) and HTR accuracy by ≈ +0.005, i.e. it is real but small; whether more HTR reference images / more HTR pair groups (a new HTR-focused labelling batch) help more than selection is a data question for the lab. A prospective arm "HTR-weighted vs random" on new growth data, evaluated on a fixed expert-judged HTR hold-out, would settle it.
4. **Prospective test with a random arm** (as in the earlier hand-offs): label a random arm and a `vopt_u`/`vopt_htr4` arm with `lap3_k10_st4` on new growth images (they can enter the graph as unlabelled nodes) and evaluate on a fixed hold-out.
5. User decision: whether to adopt `lap3_k10_st4` as the default learner of the active-learning pipeline in the paper draft (I did not touch `code/ACADEMIC_REPORT_DRAFT.md`).

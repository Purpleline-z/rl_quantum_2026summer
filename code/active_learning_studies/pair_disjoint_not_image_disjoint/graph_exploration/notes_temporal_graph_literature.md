# Literature notes — temporal edges / temporal smoothness (temporal-graph study)

Search snippets only (WebSearch, standard mode, 2026-10-13); nothing below was read in full text. "(摘要)" = from the search summary. arXiv/CVF pages are not fetched in this environment.

## What the literature suggests for the design
- **Temporal coherence as a regulariser (摘要).** Mobahi et al., *Deep Learning from Temporal Coherence in Video* (ICML 2009; [paper](https://dl.acm.org/doi/pdf/10.1145/1553374.1553469)): networks are trained so that embeddings of successive frames stay close; the related-work excerpt places this next to Laplacian SVM / graph-Laplacian penalties on linked examples. A video-embedding paper ([IJCAI 2016](https://www.ijcai.org/Proceedings/16/Papers/539.pdf), see also [this summary](https://www.researchgate.net/publication/351410480_Temporally_Coherent_Embeddings_for_Self-Supervised_Video_Representation_Learning)) combines an adjacent-frame term with a graph regulariser built from a similarity matrix over all frames. Our `tg_u*` variants (kNN term + chain term) are exactly this combination; the "unlabelled-only" and "temperature-bin" variants are our own.
- **Slowness principle (摘要).** Wiskott & Sejnowski, *Slow Feature Analysis* ([Neural Computation 2002](https://pubmed.ncbi.nlm.nih.gov/11936959/)): features of a quickly varying input that vary slowly in time tend to be invariant ones. The assumption is that the *label-relevant* state changes slower than the raw signal. For RHEED frames this is the hypothesis to test, not a given: near phase transitions the label does change within a few frames, and a first-difference penalty across such a boundary blurs it.
- **Second-order (curvature) smoothness (摘要).** Hessian-energy regularisation (Saarland ML group, [code page](https://www.ml.uni-saarland.de/code/HessianSSR/HessianSSR.htm); [Laplacian-Hessian regularisation](https://ieeexplore.ieee.org/abstract/document/6982685/)): the Laplacian penalises the first derivative along the manifold and has a constant null space (predictions flatten towards constants away from labels); the Hessian energy's null space contains functions that change linearly along geodesics. Along a run (a 1-D manifold) the second difference is the discrete analogue, so `tg_curv` lets scores drift linearly with time at no cost. Those pages are secondary summaries; the claim "better extrapolation" is the authors' own.
- **Temporal ensembling (摘要).** Laine & Aila ([arXiv 1610.02242](https://arxiv.org/abs/1610.02242)) is "temporal" in the sense of epochs (consensus of predictions over training epochs), not frames of a recording; it is not what we do here. The consistency-regularisation idea (smooth the mapping on the manifold of likely inputs) is the same family as our `cons*` graph-free control from the earlier study.
- **RHEED + time (摘要).** Reported RHEED analyses use the time axis mostly for unsupervised segmentation (PCA/K-means over a whole video, changepoint detection on frame features; [Nano Convergence 2023](https://link.springer.com/article/10.1186/s40580-023-00359-5)) and one supervised model that notes workflows "neglect the temporal continuity of material growth" and uses a transformer over frame sequences (PS-Transformer, via the same search). None of these test temporal edges inside a semi-supervised preference learner on a few hundred frames.

## What this implies for expectations (stated before the data)
1. Adjacent frames are near-duplicates in SimCLR space, so most temporal edges are already kNN edges (measured: 84–94 % of the ±1…±5 chain edges are kNN edges, `edges` table in the results). The *new* information is only in the remaining 6–16 % — mostly frames where the feature changes fast, i.e. close to transitions. These are exactly where "adjacent frames have the same label" is least safe.
2. A random-within-run permutation is an extremely harsh control (graph-mechanism work: random long-range edges destroy the gain). Beating it is weak evidence for *temporal order*; the local-shuffle and random-kNN-edge controls added here ask the sharper question.
3. Temperature is not monotone in time (RR220204A is a cooling run), so any "monotone in temperature" assumption is not used; temperature only enters edge weights / bins.

# Graph methods beyond the held-out preference endpoint: classification, unlabelled-image dose-response, harsh splits

Branch `claude/graph-endpoint-1013`, run of 2026-10-13. All tables are generated by `new_directions/ge_report.py` from the result JSONs in `new_directions/results/ge/*` (this file is built from `RESULTS_graph_endpoint.template.md`; no number is hand-copied into a table). Pre-registered blocks: confirmation 1 (seeds 8500–8534, where the success rules are judged) and confirmation 2 (8550–8584, an independent replication), frozen in `PREREGISTRATION_GE1.md` before any of those seeds ran. Development screens (seeds 8400–8419) are labelled as such and are not evidence. Same 168 labelled pair groups / 150 ideal images as all earlier work (re-split with new seeds, **not new data**), so Wilcoxon p-values are optimistic. `code/ACADEMIC_REPORT_DRAFT.md` is untouched.

## 1. Answers in one paragraph each

**(a) Classification (the paper's own endpoint: 28 outer-test ideal images).** Graph methods do **not** beat the simplest controls in any way that can be attributed to the graph. Label spreading, a 2-layer GCN, SGC and the Laplacian reward head were all at or below 1-NN (0.88) and logistic regression (0.88–0.90) on the dev seeds and, for the two carried to confirmation, in the confirmation blocks: the Laplacian-regularised *reward head* is significantly **worse** than 1-NN (about −0.03 to −0.04 accuracy, Holm ≤ 0.007 in both blocks) and than the same head without the graph term; SGC is about 0.01 below 1-NN (and 0.015–0.03 below logistic regression). The one candidate that matched the controls, Laplacian-regularised logistic regression (`laplr`), is statistically indistinguishable from plain logistic regression (its γ = 0 limit) and from its own shuffled-graph control (difference 0.000 to +0.001) — and logistic regression itself beat 1-NN in one block (confirmation 2: +0.021, uncorrected p = 0.011) but not the other (confirmation 1: +0.006, p = 0.37). So the pre-registered rule "some graph method beats 1-NN with Holm < 0.05" is met in confirmation 2 (by `laplr`) and not in confirmation 1, and in the block where it is met the gain belongs to logistic regression, not to the graph. The Laplacian term costs classification accuracy monotonically with λ (dev: 0.878 at λ = 0 → 0.812 at λ = 10): it smooths scores across kNN edges, about 20% of which join different classes. The loss falls on the (1x1) class (recall −0.12 in both blocks) while √13 gains (+0.05 to +0.07) (section 5). Dev check: a graph without ideal-image nodes (penalty only between trajectory frames) removes the classification loss (+0.001 vs the non-graph head) but also loses part of the preference gain (AUC +0.003 to +0.008 vs +0.011 for the full graph in the same runs) — a trade-off, not a free fix. The endpoint also cannot rank methods finely: 28 test images give about ±0.06 binomial noise per seed.

**(b) Do more unlabelled images help?** Formally yes, practically no. The pre-registered trend test passes (the gain of `lap3_k10` over `aw8_all` rises with the unlabelled fraction in both splits and both metrics), but the whole trend is the step from a graph with **no trajectory frames** (nodes = ideal images only; gain slightly negative) to a graph with **10% of the frames** (about +0.013 AUC); from 10% to 100% there is no consistent further increase (exploratory trend over 10/25/50/100%: confirmation 1 slopes ≈ 0 for AUC, p = 0.67–0.82; confirmation 2 slightly negative for AUC, p = 0.04 in split A, and a small positive accuracy slope in split B only, p = 0.007), and frames that occur in no pair group add nothing — for AUC they slightly reduce the gain (series 'out': slopes −0.002 to −0.005 AUC, p down to 0.002 in confirmation 2). A dev mechanism run shows the same: a graph made only of the ideal images plus the images of the labelled judgments already gives the full gain. For the planned new growth data this means: the Laplacian learner's benefit saturates at a few hundred nodes of the right kind; more unlabelled images are not where its value lies.

**(c) Harsh splits.** `lap3_k10` keeps its gain over `aw8_all` when the held-out data come from a growth run or a temperature band the training data (and graph) never saw: AUC +0.02 and accuracy +0.015 to +0.025 on both split kinds in confirmation 1, all four cells Holm < 0.003, clearly better than the shuffled and noisy-graph controls; the pre-registered rule (c) is met (see the verdict list for confirmation 2). **Important caveat:** the harsh test sets are fixed (50 decisive judgments in 28 groups for the held-out-run split, 26 judgments in 12 groups for the temperature split), so the seed-level p-values only reflect training-set variability, and confirmation 2 reproduces the result on exactly the same test judgments (it is not independent with respect to the test set). A bootstrap over the test groups gives 95% intervals that include 0 in 7 of the 8 confirmation intervals (the exception: AUC on the temperature split in confirmation 2, +0.001 to +0.053). In an exploratory dev run that holds out all three temperature terciles in turn (32 test groups, 71 judgments) the AUC gain is +0.024 with interval +0.007 to +0.041, the accuracy gain +0.011 [−0.012, +0.034]. So: the point estimates under harsh splits are as large as under the ordinary split, the controls fail, and the AUC gain is supported once the test set is large enough to resolve it; the accuracy gain is not resolved. **A harsh split where the graph claim fails (dev, exploratory):** a forward-in-time split (the last third of every run held out; 25 test groups, 36 judgments) gives `lap3_k10` a small AUC gain (+0.013, p < 0.001) and no accuracy gain (−0.001), and here the shuffled-graph and noisy-graph controls have a *higher* AUC gain (+0.052, +0.032) — the AUC gain on this split is a generic strong-regularisation effect, not evidence for the graph (accuracy: lap3 beats the shuffled graph by +0.040). The pre-registered splits (held-out run, held-out temperature) were chosen before this one was looked at, but it shows the 'beats the shuffled graph' check is split-dependent. Sensitivity (dev, section 5): the harsh-split gain depends on the graph degree — k = 5 and k = 20 give clearly less (AUC +0.004 / +0.011 on held-out runs, +0.012 / −0.002 on the temperature split, versus +0.018 / +0.020 for the frozen k = 10). Per-type view (section 5, descriptive): on the held-out-run split the accuracy gain sits entirely in the HTR judgments (+0.15, 7 test judgments, bootstrap interval +0.05 to +0.22 in both blocks; other types −0.006), on the temperature split it sits in the other types (HTR −0.006, others +0.04); with 7 HTR test judgments in a handful of groups this is a hint for the lab's HTR question, not a result — and it is not consistent across harsh splits (dev, same computation: temperature terciles in turn +0.003 on 12 HTR judgments; forward-in-time split +0.03 on 8), so on harsh splits it is at noise level; the only stable HTR signal is the ordinary-split one below. Exploratory dev result (section 5): letting the held-out condition's *unlabelled* frames into the graph gives small and inconsistent extra gains — about +0.010 AUC on held-out runs when 50–100% of the frames are added (uncorrected p = 0.02; not at 25%), and no gain or a slight AUC loss on the temperature split (−0.008 at 25–50%); the transductive arm with the test images adds +0.014 AUC (runs) and +0.012 accuracy (temperature). Dev evidence only; no monotone dose-response.

**Something the lab may care about (descriptive, not pre-registered):** on the ordinary splits `lap3_k10` improves HTR accuracy over `aw8_all` by +0.02 to +0.04 in all four (block × split) cells of the confirmation dose runs (uncorrected p ≤ 4e-4; section 5), (the harsh-split HTR numbers above are too few and too inconsistent to add to this).

**What did not work or was not confirmed:** every graph classifier except the logistic-regression limit; λ chosen by internal validation (dev only: picked λ = 1 in 68% of fits and was not better than fixed λ = 3).

## 2. What was run
Protocol extensions (all marked in `PREREGISTRATION_GE0/GE1.md`): (E1) classification endpoint on the paper split with INDUCTIVE (test ideal images not nodes; attach to nearest nodes) and TRANSDUCTIVE (test images are unlabelled nodes; looser) graph protocols reported separately; labelled data = the 88 reference images only. (E2) dose-response: graph nodes = ideal images + a fixed per-seed fraction of the trajectory frames. (E3) harsh preference splits from file-name metadata (3 growth runs; temperature): leave-one-run-out and held-out top temperature tercile, with all frames of the held-out run/band removed from the graph. The ordinary split is **already strictly image-disjoint** (asserted in `judgment_unit_study.Context`: no evaluation image occurs in any training or candidate group), so a separate "image-disjoint" split was not needed; what the ordinary split lacks is run/time separation (neighbouring frames of one run can sit on both sides). File-name metadata parses for 284 of 284 pair-group images (run id, temperature, clock), so the condition splits are feasible; only 3 runs exist (111/108/65 pair-group images); 104 of the 168 pair groups compare images from two different runs, and those touching the held-out run are dropped from training in the harsh splits.

Candidates (4): `lap3_k10` (Laplacian-regularised `aw8_all` head), `laplr`, `sgc`, `lap3_ref`; controls: `nn`, `logreg`, `aw8_ref`, `aw8_all`, shuffled graph (`*_shuf`), noisy graph (`lap3_k10_n3`). The control numbers: our 1-NN reproduces the baseline branch's five paper-seed values exactly (0.857, 0.857, 0.893, 0.821, 0.929; unit-tested); logistic regression gives mean 0.857 on those seeds (baseline branch: 0.850). Reference numbers from `claude/classification-baselines` (read only, not merged): SimCLR 1-NN 0.871 ± 0.041, SimCLR logistic regression 0.850, raw-pixel logistic regression 0.886, random-weight ResNet-18 1-NN 0.886–0.900, fine-tuned SimCLR 0.893 — all within the ±0.06 binomial noise of one another.

## 7. Limitations
Same 168 pair groups and 150 ideal images in every seed (only the split changes) → optimistic p-values; the classification endpoint has 28 test images per seed; the harsh splits have fixed test sets with 3 runs / one temperature band (see the bootstrap caveat in 1(c)); the dose-response confirmation rule is satisfied by the p = 0 step alone (reported with the plateau analysis rather than hidden); frozen SimCLR features and a small head — the graph quality lever (better encoders) and end-to-end fine-tuning are GPU tasks (`GPU_TASKS_graph_endpoint.md`); the dev seeds 8400–8419 overlap seeds used by the sibling selection session (different question, no dev number reused); literature notes rest on search-result summaries (no paper text opened).

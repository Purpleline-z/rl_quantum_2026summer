# GPU / lab tasks left for you (graph selection under the tuned learner)
Everything in this study ran on CPU with frozen SimCLR features. Things that need a GPU, the lab, or your decision:

1. **End-to-end fine-tuning check (GPU, Colab).** Re-run the comparison Random vs `tdc` (typed decisive coverage) vs `qcov_alloc` vs `vopt_u` in the end-to-end model with the anchor weight raised from 0.25 to 8 in `Experiment.train` (same recipe as `new_directions/NEW_DIRECTIONS_RESULTS.md` §6). The graph is built on the frozen encoder's features, so only the learner changes. Expect small differences (+0.005 to +0.01 AUC in the frozen setting).
2. **Prospective test with real labelling (lab).** The one effect that is graph-specific and large is *decisive enrichment*: the typed-coverage rules ask for 62–65% decisive judgments versus 50% for random (generated mechanism table, `TABLES_graph_selection.md`). That saves labelling effort even when the endpoint gain is small. A prospective arm: 40 new comparisons chosen by `tdc` versus 40 random, count the fraction of ties/not-applicable answers. This is cheap and answers the question the offline data cannot (whether the decisive predictor transfers to new image pairs).
3. **Decide about HTR.** Under `aw8_all`, variance-reduction selection (non-graph) improves HTR accuracy/AUC by about +0.02 (confirmed, 35 seeds); the lab-relevant question is whether that holds for the real HTR set. If yes, the practical recommendation is `vopt_u@aw` or `gvopt_lap3@aw` for HTR-focused rounds (`vopt_u@aw` loses 0.011 other-type accuracy in split B, `gvopt_lap3@aw`/`qcov_alloc` do not).
4. **More ideal images for HTR** (from `new_directions`): still open; the anchor loss is what drives the learner now.
5. **If new pair groups become available:** every p-value here is optimistic (same 168 groups). A fresh set of groups with a Random arm is the only way to turn these into evidence about new data.

# 一页总结:换一个"表示"能不能让 `lap3_k10_st4` 更好?(表示研究,分支 `claude/representation-20261013`)

**结论(预先登记的确认,种子 8650–8684,35 个种子,划分 A、B):没有确认。** 冻结的 4 个候选(① 图用 SimCLR 最后一层、头用 ImageNet⊕SimCLR 拼接;② 只用 ImageNet ResNet-18 特征;③ SimCLR 第 3 层;④ 7 个确定性视角的特征平均)都**没有**让 `lap3_k10_st4` 在留出配对组的 AUC 和准确率上变得更好:16 个预先登记的差值里 15 个是负的,最大的 AUC 提升只有 +0.0002;含 ImageNet 的候选在准确率上显著变差(−0.017 到 −0.024,Holm 校正后仍显著)。按预先登记的规则,"控制组"(打乱图、容量控制)没有进入正式检验。

**能说的:**
1. 此前的"学习器侧增益"在新种子上**重复了**:`lap3_k10_st4` 比调好的无图对照高约 +0.016 AUC、+0.014~+0.017 准确率。
2. 换表示不能在此之上再加分;4 个候选都保留了对无图对照的 AUC 优势(+0.007~+0.016),说明增益来自图,而不是来自某个特定表示。
3. 开发阶段(种子 8600–8619,只是观察,不当证据):PCA 白化明显变差(−0.04~−0.07 AUC);无图的头换任何别的表示都更差;学习率再调、5 头集成(只多 +0.002 AUC)都没有改变结论。
4. 一个**探索性**信号:候选①把 HTR 对数损失改善了 +0.07~+0.09(35/35 个种子都更好)、HTR 准确率 +0.02,但代价是总体准确率 −0.017~−0.019、√13 类准确率 −0.04~−0.05。事后在开发种子上做的对照显示:这个 HTR 改善需要图(打乱图后大幅崩溃),也不只是"多加维度"(比 SimCLR⊕随机投影的容量对照更好),但它并不让候选①整体更好。HTR 只有每个划分约 10 个留出判断,样本很少。

**不能说的:** 不能说"表示一定没用"。这里只试了本地能拿到的表示:SimCLR 第 3/4 层、缓存的 ImageNet-ResNet-18 特征、视角平均、白化;HuggingFace / torch hub 在这个环境里返回 403,所以 DINOv2、CLIP 之类**没法试**;没有微调;学习率/步数没有为每个表示重新调(只做了 4 个种子的小检查,变化 ≤0.005 AUC);同样是那 168 个配对组重新划分,p 值偏乐观。

**下一步(见 `GPU_TASKS_representation.md`):** 有网络/GPU 时试更强的冻结编码器,或在全部无标注生长图上继续微调 SimCLR(这里唯一没允许的表示杠杆);HTR 方面更可能有用的是新增 HTR 标注数据,而不是换表示。

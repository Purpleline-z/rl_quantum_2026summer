# Tasks for the user (need GPU, new data or lab time) — transductive / forward-in-time study

1. **Prospective test on a new growth run (the only real test of "generalisation to a new run").** Everything here re-uses the same 168 labelled groups / 284 frames of three runs; a null or a gain at this effect size means nothing about a fourth run. Protocol: label pair groups of the new run in time order (e.g. every ~20th frame against a frame of an earlier run, all four types) while the run is grown; at each labelling checkpoint score the *next* frames with (a) `BASE` = `lap3_k10_st4` on the past-only graph and (b) the causal transductive learner (`L:trans_win`, node set = every frame that exists when scoring); compare AUC / accuracy / log-loss on the later labelled groups. Code: `new_directions/td_core.py` (`make_forward_ctx` is the offline version of this; replace the calendar order by the new run's frame numbers). ≥ 150 new judgments per checkpoint are needed to resolve +0.01 AUC at the group level.
2. **Frame-level labels along a run** (carried over from `GPU_TASKS_temporal_graph.md`): the only way to learn whether the score at a not-yet-labelled frame is better predicted by its time neighbours than by its feature neighbours; here the transductive gain concentrates on judgments far (> 0.1 cosine distance) from every past node, where feature neighbours are weakest.
3. **Test-time adaptation of the encoder (GPU).** All confirmed gains use frozen SimCLR features; the transductive gain is a head-side effect. Continue SimCLR (or BYOL/DINO-style) training for a few epochs on the images that exist at the cut (past + scored frames, no labels), re-extract features, rerun `L:trans_win`; compare with the frozen version at the same six cuts (`td_run.py` needs only the feature cache path changed). Expected to matter for the anchor-far judgments (representation, not head, is the bottleneck there).
4. **Other frozen encoders with transduction (GPU / unblocked HuggingFace)**: DINOv2, CLIP; earlier representation screens were run without the transductive node sets.
5. **Gradual self-training at scale**: pseudo-label future frames in time order in several rounds (Kumar–Ma–Liang style) with an end-to-end encoder; the head-only co-training tried here (2 rounds, 100–300 pairs per type) was mixed (helps the far window, hurts the near one).
6. **Dose-response of the unlabelled future** inside the forward protocol: how many future frames (and how far ahead) are needed — `trans_test` (only the scored frames) vs `trans_win` vs `trans_fut` suggests that the gain needs frames *between* the past and the scored frames; a controlled sweep (add every k-th frame) would tell how fast the lab must stream images into the graph.

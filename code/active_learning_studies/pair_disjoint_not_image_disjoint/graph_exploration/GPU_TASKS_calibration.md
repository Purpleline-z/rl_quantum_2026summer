# GPU / lab tasks left for the user — calibration of the Laplacian reward head

Everything in this study is CPU-only (frozen SimCLR features, small head). What needs more than that:

1. **End-to-end fine-tuned reward model: does the per-type scale pattern survive?** Re-fit the per-type temperatures (RT13 ≈ 0.3, c(6x2) ≈ 0.7, HTR ≈ 0.7, (1x1) ≈ 1.3 for the frozen-feature head) for a fine-tuned or larger-encoder model (DINOv2 / ImageNet features via `build_feature_cache.py`, or end-to-end fine-tuning with order-independent full-batch training). Recipe: `cal_run.py` equivalent with the new head; the calibrators in `nd_calibration.py` only need a function that returns logits for a (train, held-out) split. Expected: the constants change with the encoder, the *method* (per-type temperature from out-of-fold logits centred on a development prior) carries over.
2. **Laplacian regulariser in the end-to-end model with a per-type weight** (RT13 penalty small or off, as `claude/graph-mechanism-20261013` found useful for ranking) and then calibrate: here the RT13 score compression is removed at the source instead of after the fact; the development side run (frozen features, `lap3_k10_st4_rt13off`) says the raw log-loss improves but accuracy in split A drops and the calibrated log-loss is not better — worth testing with a better encoder.
3. **A genuinely held-out calibration set (lab task, no GPU):** 60–100 fresh pairwise judgments per type (especially RT13 and HTR, where the head is most mis-scaled) from *new growth runs*, never used for training or for choosing anything. With 5–13 decisive labelled judgments per type per run, a within-run calibrator cannot estimate four temperatures; the constants of this study were estimated on development re-splits of the same 168 pair groups and are therefore not independent of the confirmation data.
4. **Downstream use as a reward:** if the calibrated probabilities are to drive an RL / Bayesian-optimisation loop, check calibration where the policy actually goes (anchor-far, unseen growth conditions); temperature scaling is not expected to fix mis-calibration under shift (literature summaries in `notes_calibration_literature.md`), so a prospective check on new growth trajectories is needed.

# GPU / larger tasks left for the user (graph-mechanism branch)

Everything on CPU with the frozen SimCLR encoder is done (see `RESULTS_graph_mechanism.md`). The dose-response and the plateau of all CPU-side graph variants say that, on this encoder, a better graph by itself does not give more than about +0.02 AUC over `aw8_all`. If graph quality is the lever, the lever has to be pulled where the CPU cannot reach:

1. **A better encoder for the graph (and for the head).** DINOv2 / ImageNet ResNet / a SimCLR re-pre-trained on all 1124 trajectory + 154 ideal images (and Yao's new trajectories). Rebuild `feature_cache_all.pt` and `feature_layers_all.pt` (`nd_core.feature_cache`, `nd_gm_layers.py build`), then rerun the frozen candidates of `PREREGISTRATION_GM1.md` and the dose-response (`bash scripts_gm/run_gm.sh ...`, new seeds >= 8600) and check whether (i) the ideal-ideal same-class share of the kNN graph rises above ~0.81 and (ii) the gain over `aw8_all` rises with it. This is the cleanest test of "gain follows graph quality"; the noise dose already shows the downward direction only.
2. **End-to-end Laplacian term with fine-tuning** (graph loss on the encoder's own features instead of frozen ones). Needs a protocol decision (the evaluated model changes).
3. **Learned graph** (e.g. Kalofolias-style smooth-signal graph learning, or a graph from a metric learned on the 154 ideal images with cross-fitting; our LDA topology was too crude: it was circular and harmful at strong weight) — needs a cross-fitted evaluation of graph quality so that ideal-image labels used to learn the metric are not reused to score it.
4. **Prospective test** on newly grown trajectories with new expert comparisons (all current evidence reuses the same 168 pair groups).
5. **Type-specific graphs**: RT13 did not benefit from the Laplacian while 1x1 and HTR did (development, and confirmation exploratory rows); a per-type feature subspace for the graph (needs a better encoder to be meaningful).

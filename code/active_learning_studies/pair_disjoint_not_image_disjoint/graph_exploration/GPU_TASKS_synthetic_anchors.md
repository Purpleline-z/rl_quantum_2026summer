# GPU / data tasks left for the user — synthetic-anchor study

CPU findings (`RESULTS_synthetic_anchors.md`): the kinematic simulator's images do not help as anchors; the anchors' *image style* does matter (direct-beam masking, 16-bit PNG handling); the large open gap — generalisation to a new growth run — is untouched. What needs resources not in the container:

1. **Fix the ideal-image preprocessing in the lab pipeline (no GPU).** 18 of 154 ideal images (10 HTR, 8 RT13) are 16-bit PNGs that the loader clips at 255; (1x1)/c(6x2) ideal images are uncropped (direct beam visible) while trajectory frames are not. Decide with the lab what the intended preprocessing is (crop to the trajectory-frame window? rescale 16-bit by 255/65535?) and re-encode the ideal images accordingly; the paper's anchors and any external classification endpoint on the 28 outer-test ideal images are affected.
2. **The existing simulator archive** (`classifier-sto-v6-dual-raster__p656_aligned_peak.zip`, 2250 images) was not available here. Rerun the study's feature-space gap table (`syn_gap.py` on a bank built from those images; `syn_bank.py` shows the encoding) and the zero-pair-label diagnostic (`syn_anchor_only.py`): a bank that is closer to real images than the kinematic renderer (dual-raster, dynamical effects, real structure factors) is the only way the synthetic idea can be tested properly. The HTR type needs a physical model from the physics team (lattice, expected streaks); the surrogate used here is arbitrary.
3. **End-to-end / GPU tests of synthetic data.** With frozen SimCLR features the synthetic images stay perfectly separable from real ones (real-vs-synthetic AUC 1.0); fine-tuning the encoder with synthetic + real images (domain-adversarial or style-transfer on the synthetic images) was not possible on CPU. A cheaper first test: SimCLR features of CycleGAN-style translated synthetic images.
4. **New growth runs with pair labels** (even a few dozen groups) — the only test of the central claim (generalisation away from typed anchors / to a new run). All "time" and "far" splits here are inside the same three experiments.
5. **Frame-level type labels along one run** (see `GPU_TASKS_temporal_graph.md`) would also give a fixed labelled test set made of *trajectory-style* images, which is what the masked-anchor / gate results actually need.

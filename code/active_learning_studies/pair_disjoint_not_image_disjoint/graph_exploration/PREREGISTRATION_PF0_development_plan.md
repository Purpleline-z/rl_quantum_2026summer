# Development plan PF0 (written before any development result of the learner screens; branch `claude/physics-features-20261014`, started 2026-10-14 02:47 UTC)

**Question.** Every representation tried so far is appearance-based (SimCLR, ImageNet). Reconstruction type is a periodicity property of the diffraction pattern. Does a physics-informed descriptor computed from raw pixels (no learning) improve `lap3_k10_st4` — as head input, as graph metric, or as anchor-matching signal — in particular on judgments far (> 0.01 cosine distance) from every typed anchor?

**Endpoints.** Standard: held-out pair-group AUC, accuracy, log-loss (splits A, B; budgets 10/20/40/60; 3 random label sets per seed identical for all learners; judgment-unit protocol). Primary extra: anchor-far stratum (`pf_tables.py`: both images of a held-out judgment are > 0.01 from the nearest typed ideal image in centred SimCLR geometry = red-team definition; AUC where both outcomes occur). Reported with every candidate: time-blocked split (`rt_blocked`), per-type accuracy (HTR). Baseline `lap3_k10_st4`; tuned graph-free control `aw8_all_st2lr0.5`; every graph claim gets a shuffled-graph control; capacity control = concatenation with a fixed random Gaussian projection of SimCLR of the same dimension as the physics block (`prd`).

**Protocol extension (stated as required).** The learner may use features computed from the raw pixels of every image that may enter the graph (trajectory frames and ideal images; no learning, deterministic code in `pf_extract.py`). No pixel, statistic or label of validation/test pair-group images or of the seed's outer-test ideal images enters nodes, standardisation constants or labels (z-scores use only the context's allowed graph nodes, SHA-256 exclusion as `nd_graph_learner.GraphData`; unit test). Seeds: development 10600–10619, confirmation 1 = 10630–10664, confirmation 2 = 10665–10699 (`nd_core.PF_*`).

**Data audit (done before the screens, not a learner variant).** 18 of the 154 ideal images (10 HTR, 8 RT13) are 16-bit PNGs of size 780x580 from another camera set-up (porthole visible). All loaders of the repository use `Image.open(p).convert("L")`, which clips 16-bit values at 255: these 18 images are fed to SimCLR as saturated white discs (pairwise cosine of their cached features 0.9999). They are anchors of the HTR and RT13 classes of every `aw8_all`-family learner. `pf_build_f16.py` re-encodes them correctly (value/257, resampled to the 656x492 frame) with the same frozen encoder; variant `pf_f16` tests whether this matters for preference learning (no physics involved).

**Physics extractor (`pf_extract.py`, `PHYSICS_FEATURES.md`).** horizon (shadow edge) detection; specular spot; horizontal intensity profiles of five vertical bands relative to the specular row, baseline-corrected (20th-percentile filter), amplitude-normalised; descriptor blocks: pixel-unit folded profiles, profiles in units of the estimated integer-order spacing, fractional-order peak table (1/13 … 3), Fourier amplitudes at periods a/m (m = 1, 2, 3, 6, 13/2, 13/3, 13), background / brightness, specular width. Feature sets: `pfa` (pixel profiles + background + width, 136-d), `pfb` (peak table + Fourier + background + width + spacing, 126-d), `pfc` (all, 366-d).

**Validation before use (done).** Seed-wise: train = references + utility ideals, test = the seed's 28 outer-test ideals (as the paper's classification endpoint), 20 seeds 10600–10619, 1-NN (cosine, centred z-scores) and logistic regression, compared with SimCLR 1-NN. Result table: `RESULTS_physics_features.md`.

**Development screens (seeds 10600–10607 first, 8 seeds, splits A,B; at most ~12 learners at a time, all paired with `lap3_k10_st4`).**
1. head input: `pf_pfa_h` (physics alone), `pf_pfa_hs` / `pf_pfb_hs` / `pf_pfc_hs` (physics ⊕ SimCLR, L2-normalised blocks, norm-matched), graph = SimCLR;
2. graph metric: `pf_pfa_g` (graph from physics alone, head SimCLR), `pf_pfa_gs` (fused similarity), `pf_pfa_hgs` (both);
3. anchor matching: `pf_q_pfa` (lap3 + ranking term towards the physics-prototype class posterior), with SimCLR-prototype control `pf_q_s4`;
4. data fix: `pf_f16`;
5. capacity control `pf_prd_hs`; shuffled-graph controls for every graph-using candidate that survives.
Stage B (extension to 20 seeds, variants of the best 2–3 families, schedule/scale checks) and the anchor-far and time-blocked checks follow. All variants tried are listed in the log whether they work or not. At most 4 candidates (+controls) are frozen in `PREREGISTRATION_PF1.md` and committed before any confirmation seed is run; confirmation 1 on 10630–10664 once, confirmation 2 on 10665–10699 once, if time allows.

**Success rule (fixed now).** A candidate is confirmed iff its AUC and accuracy differences to `lap3_k10_st4` are positive in both splits, ≥ 3 of these 4 tests have Holm p < 0.05 (family: candidates × 2 splits × {AUC, accuracy}), the anchor-far AUC gain (pooled over both splits) is positive with a bootstrap 95 % interval excluding 0, and it beats its shuffled-graph and random-projection controls (positive and uncorrected p < 0.05 in at least one split). A clean finding "physical features separate the ideal images but do not help preference learning" is a result too; then the analysis of why (feature plots by type, images) is part of the deliverables.

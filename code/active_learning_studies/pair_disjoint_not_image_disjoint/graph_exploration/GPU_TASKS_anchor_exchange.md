# GPU / lab tasks left for you (anchor-exchange study)
Everything here ran on CPU with frozen SimCLR features and the existing data. What cannot be answered from existing data:

1. **Prospective experiment: typed labels of NEW trajectory frames vs new pairwise judgments (lab).** Only ideal images (about 154) carry type labels, trajectory frames have none (the absolute-label file has 18 'Bad' images), so the exchange rate in `RESULTS_anchor_exchange.md` is for ideal-image anchors; whether a typed label of a trajectory frame is worth the same is a hypothesis. Design: pick a growth run (or the next one) as a fixed test set of pair groups; give the model the existing 168 groups; then spend equal LABOUR (measure minutes per typed label and per pairwise judgment first) in two arms: (A) K new pairwise judgments on frames of the new run, (B) typed labels of M frames of the new run, M chosen with the exchange rate (see the table: in the low-budget range one typed label ≈ 2 pairwise judgments for the first ~12 anchors and at least that for the next ~17 (extrapolated), strongly diminishing after ~30). The loss already accepts any labelled image as an anchor (the anchor ranking term), so arm B needs no new code: pass the labelled trajectory frames as anchors. Measure held-out pair preference AUC/accuracy and per-type accuracy; HTR separately.
2. **Cost measurement.** The exchange rate is in labels; the lab's decision needs minutes (or euros) per typed label and per pairwise judgment. A 20-minute timing session with the two labelling interfaces turns the table into a budget rule.
3. **Active anchor choice with the lab in the loop.** Nothing in the development or confirmation data favours a particular rule for the preference endpoint; diversity-based rules (feature k-center, TypiClust) improved the external type accuracy on dev seeds (see the results). If anchors are chosen for classification quality rather than preference quality, label with a diversity rule; this should be tested on a new external set of ideal images (the 28-image test has about ±0.06 binomial noise per seed).
4. **End-to-end fine-tuning (GPU).** The anchor term in `Experiment.train` is one random reference pair per mini-batch with weight 0.25; the study's dose-response is for the frozen-feature head. Re-run the dose-response levels with the anchor weight raised (see `new_directions/NEW_DIRECTIONS_RESULTS.md` section 6) and the Laplacian term on the same nodes.
5. **HTR.** On the development and confirmation data typed anchors did not help HTR (slightly negative); the HTR type is already at AUC about 0.99 without anchors. Whether more HTR pairs, more HTR ideal images, or neither is the right spend is open; a prospective HTR-only test set is the only way to tell.

# GPU / data tasks left for the user — temporal-graph study

The CPU study found no gain from temporal edges on frozen SimCLR features (`RESULTS_temporal_graph.md`). What it could not test:

1. **Frame-level labels along one run (data, not GPU; the most valuable item).** The temporal idea rests on "adjacent frames usually carry the same reconstruction type", which nobody has measured: only 284 frames have any label, and they enter only through pairwise comparisons. Ask the physics team to give absolute type labels (or a "same type as the previous frame: yes / no / transition" flag) for ~150 consecutive frames of one run, including a transition region. That gives (a) the label-change rate between adjacent frames, (b) a direct test of whether feature-distant temporal neighbours (the 6–16 % of chain edges that are not kNN edges, which hurt here) are exactly the transition frames, (c) a fixed test set for temporal methods that is not made of near-duplicates of the training frames.
2. **New growth runs with pair labels** (even a few dozen groups) as a prospective, run-disjoint test set; the three existing runs are the whole data set, so every "time" split here is a split inside the same three experiments.
3. **Temporal coherence inside the encoder** (needs a GPU): fine-tune or re-pretrain the encoder with an adjacent-frame consistency / slowness loss restricted to non-transition frames, then rebuild the kNN graph from it. On frozen SimCLR features the temporal neighbours are already feature neighbours (84–94 %), so a temporal signal can only add information in a representation that is *not* already invariant to adjacent-frame differences. Earlier time-contrastive adapters on frozen features were negative; the end-to-end version is untested.
4. **Higher frame rate / temperature-aware acquisition** (experiment design): the strict 25-frame buffer removes 83–98 % of the nodes in the standard splits because held-out images are spread over all three runs; a split by *segments* of runs with a long guard band needs more or longer runs than exist.
5. If a second encoder (ImageNet / DINOv2) is built for the other studies, rerun `tg_dec5` / `tg_curv` with it on fresh seeds (spare seeds 9220–9249 of this study's block are unused; confirmation seeds 9250–9284 are used).

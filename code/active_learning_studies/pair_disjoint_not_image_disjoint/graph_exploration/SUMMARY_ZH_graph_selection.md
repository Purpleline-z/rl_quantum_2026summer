# 一页中文摘要:调好学习器(aw8_all)之后,图选择规则还能帮忙吗?(Prompt 2,分支 `claude/graph-selection-htr-1012`,2026-10-12)

完整结果和所有表格(脚本生成)在 `RESULTS_graph_selection.md` / `TABLES_graph_selection.md`。以下全部基于**同一批 168 个标注配对组**(换随机种子重新划分,不是新数据),冻结 SimCLR 特征,CPU 完成。

## 先说结论(不夸大)
1. **图规则在调好的学习器下,相对 Random 的提升很小(约 +0.005 到 +0.012 的准确率/AUC),但方向一致。** 两个"类型感知覆盖"规则(`tdc` = typed_decisive_coverage;`qcov_alloc` = 带类型配额的覆盖)在 105 个新种子上合并后,常规和冷启动、两个划分、准确率和 AUC 的 16 个格子里,置信区间全部在 0 以上(描述性,不是检验)。
2. **按预先登记的判据,结果是"有时过、有时不过",我不会称它是干净的成功。** 判据 = 图规则相对 Random 的准确率**和** AUC 在两个划分里 Holm 校正后都显著。S1(35 个新种子)差一点:常规起点 `qcov_alloc` 四格里三格过(B 划分 AUC 的 Holm = 0.062),`tdc` 两格过;冷启动 AUC 格子显著、准确率格子不显著。S2(30 个新种子,重复检验)没过。**S3(40 个新种子)过了两次:`qcov_alloc`(常规起点,四格 Holm ≤ 0.033)和 `tdc`(冷启动,四格 Holm ≤ 0.014)。** 合计 12 次"规则 × 块"检验里 2 次过,都在 S3。S1/S2/S3 都是我看了前一轮结果以后才决定要做的,所以"S3 过了"不能当成独立的证实。
3. **图本身有一点真贡献,但很小。** 和"把类型后验打乱"的对照相比,AUC 差在 12 个(块 × 划分)格子里 11 个为正(4 个未校正 p < 0.05);和"只用类型"的对照相比,12/12 为正(7 个 p < 0.05)。S3 冷启动里两个规则在两个划分上都显著优于打乱对照。
4. **图真正做到的事:找出"有结果的"判断。** 标签传播得到的类型后验让 `tdc` 选出约 65% 的 decisive 判断(Random 是 50%;后验打乱或去掉后只有 45–49%,比 Random 还低)。但这对终点帮助不大:开发种子上的"神谕"诊断(直接用真实 decisive 标记,批次 100% decisive)并没有比真实规则更好。
5. **为什么提升天花板这么低:** 在 `aw8_all` 学习器下,Random 的学习曲线几乎是平的(10→60 个判断,AUC 只涨约 0.007–0.024)。选择规则的 +0.005~+0.012 已经是"多给 50 个随机标注"所能带来的相当大一部分。要看到"大幅优于随机",在这个设置下几乎没有空间。

## HTR(实验室最关心的类型)
- 预注册判据 B(HTR 准确率和 AUC 增益 Holm 后显著,其他类型准确率损失 ≤ 0.01)**满足**:新种子 8300–8334 上,`gvopt_lap3@aw` 和 `qcov_alloc` 在两个划分里 HTR 准确率与 AUC 都显著(Holm ≤ 0.04),其他类型准确率没有下降;`vopt_u@aw` 增益最大(HTR 准确率 +0.025/+0.019)但在 B 划分其他类型准确率少了 0.011,按判据不算。
- **但这不是图的功劳**:它们的打乱图对照、**完全不用图**的更强岭先验设计(`vopt_ridge10@aw`)、以及不用图的"HTR 优先级"设计(`htr_vopt_prio@aw`)增益一样大甚至更大。结论:在调好的学习器下,**方差缩减式的选择**能改善 HTR;图不是起作用的成分。
- 提示要求的"HTR 与 RT13 后验模糊 / 桥图像"规则:只在开发种子上筛过,没有稳定的图特有优势(给 `vopt` 加模糊权重和加"HTR 优先"效果一样),没有进入确认。

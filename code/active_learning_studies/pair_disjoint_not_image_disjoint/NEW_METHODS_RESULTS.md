# New acquisition methods versus Random (overnight study)

Branch `claude/new-methods`. Research log: `/NEW_METHODS_LOG.md` (repository root of the branch). All confirmatory tables: `results/new_methods/CONFIRMATORY_TABLES.md` (generated by `new_methods_final_tables.py`).
Pre-registrations (each committed before the confirmatory cells existed; the commit hash is at the end of each file): `NEW_METHODS_PREREGISTRATION.md` (1), `_2.md`, `_3.md`, `_4.md`, `_5.md`, `_6.md`.

## 1. Summary

- **Result.** Under the protocol of the judgment-unit study (one (pair, type) judgment per query, budget 10/20/40/60 judgments, Splits A and B, single-shot and sequential, frozen encoder, **re-tuned head schedule**), rules that reduce the posterior variance of the preference head choose judgments that are significantly better than random ones. On two independent sets of 35 new random splits (seeds 700-734 and 800-834) the simple I-optimal rule `vopt_u` improved decisive accuracy by +0.010 / +0.017, AUC by +0.006 (nominal p 0.03, Holm 0.13) / +0.013 (Holm 0.0004) and log-loss by +0.007 (n.s.) / +0.035 (secondary; nominal one-sided p < 0.001). The second run was pre-registered as a replication of the family (4 methods x {AUC, accuracy}, Holm over 8): **all 8 tests are significant**.
- **The effect is not specific to the new rule.** Fisher D-optimal design (Active Reward Modeling) and BALD x P(decisive) under the last-layer Laplace posterior give about the same gains (accuracy +0.015 to +0.016, AUC +0.007 to +0.010 on seeds 800-834). What does not work: plain uncertainty sampling (about 0 or negative everywhere), relation-aware core-set (accuracy +0.002, AUC +0.0005 on seeds 700-734), the neural-tangent-kernel version of the design, type quotas, outcome-informativeness factors.
- **Cold start: the gains are 2-3x larger and significant on all three metrics.** With 10 random judgments as the initial set (pre-registration 3, seeds 900-934, Holm over 12 tests, all p < 0.001): `vopt_u_inf1` log-loss +0.061, AUC +0.020, accuracy +0.024 (86-91% of seeds better); `vopt_u` +0.055 / +0.018 / +0.019; Fisher +0.038 / +0.017 / +0.021; BALD x P(decisive) +0.056 / +0.019 / +0.019.
- **Type-targeted and priority-weighted design (the lab's HTR goal).** Restricting the queries to HTR judgments and designing within them (`vopt_htr`, pre-registration 4, seeds 1000-1034, 12 tests, all significant) improves HTR accuracy by +0.071, HTR AUC by +0.074 and HTR log-loss by +0.25 over Random, and by +0.021 / +0.011 / +0.043 over random selection among HTR judgments (same label allocation), but costs the other types (accuracy c6x2 -0.030, 1x1 -0.015). A **soft priority weight** (`vopt_hw4`: gain of HTR candidates x 4; pre-registration 5, seeds 1100-1134, 5 tests, all Holm < 0.0001) gets HTR accuracy +0.067, HTR AUC +0.058, HTR log-loss +0.183 **and** all-type accuracy +0.016, all-type AUC +0.014, without losing on the other types (sqrt13 +0.009, c6x2 +0.009, 1x1 -0.002); relative to un-prioritised `vopt_u` it adds HTR accuracy +0.019, AUC +0.014, log-loss +0.054 and changes nothing elsewhere.
- **Cross-world replication (pre-registration 6, seeds 1200-1234).** Rules applied in one image-disjoint half of the 168 groups and evaluated on all groups of the other half (129-135 decisive test judgments; both directions pooled; Holm over 12): `vopt_u` log-loss +0.017 (Holm 0.003), AUC +0.0067 (0.002), accuracy +0.013 (<0.0001); `vopt_u_inf1` +0.021 / +0.009 / +0.017 (all < 0.001); BALD x P(decisive) +0.019 / +0.006 / +0.015 (all < 0.01); Fisher AUC +0.0046 (0.034), accuracy +0.0075 (0.005), log-loss n.s. The two directions differ: H1 -> H2 gains are small (`vopt_u` AUC +0.002, p 0.12; Fisher and BALD AUC slightly negative), H2 -> H1 large (AUC +0.011 to +0.017). So the effect holds on disjoint data but depends on the world; `vopt_u_inf1` is positive in both.
- **The benefit fades with the number of labels already in hand.** `vopt_u` accuracy gain in Split B (dev seeds): cold start of 10 random judgments +0.019 (pre-registered), about 30 judgments (10 initial groups) +0.017, 20 groups +0.007, 40 groups +0.001, 60 groups (about 175 judgments) -0.003; AUC +0.018 / +0.007 / +0.0003 / +0.0002 / -0.0013. With 60 initial groups no rule helps (uncertainty, BALD x P(decisive), Laplace BALD, gap, core-set, uncertainty+diversity, Cluster-Margin all within about +-0.007 accuracy and +-0.002 AUC), and the HTR priority gives nothing (HTR accuracy +0.001). In this small data set the practical benefit of acquisition is a small-label-set effect; the lab's existing labels (hundreds) would already be past it, so the decisive test is on genuinely new data.
- **It depends on the head being trained well.** With the old schedule (lr 0.01, 100 steps) the gains of the pre-registered methods vanish (`vopt_u` AUC +0.0007, accuracy +0.004; `vopt_u_inf1` AUC +0.006, accuracy +0.008, n.s., 20 seeds). The re-tuned schedule (gentler, per budget) makes Random a stronger baseline in log-loss but lets design-based selection show its effect on ranking metrics.
- **Honest limits.** The seeds are new random splits of the same 168 pair groups (521 judgments), not new data; Wilcoxon p-values are optimistic because seeds resample the same groups. Effects are modest in the main protocol (accuracy +1 to +2 points, AUC +0.006 to +0.013) and the first confirmation (seeds 700-734) was weaker than development (AUC +0.006 versus +0.009; winner's curse), so the realistic main-protocol estimate is the pooled one (70 seeds, post hoc): `vopt_u` AUC +0.0093, accuracy +0.0131, log-loss +0.0211. The hindsight-oracle ceiling is far higher (accuracy +0.04 to +0.05, log-loss +0.16 to +0.20 at 10-60 judgments), but the true utility of a single judgment is not predictable from any observable feature we tried (Spearman |rho| <= 0.06).

## 2. Methods

All rules score a candidate that is one (pair, type) judgment, with the head of its own type k; they never use the hidden outcome of an unrevealed judgment (unit-tested). phi = difference of the hidden-layer activations of the two images (256-d); w = p(1-p) with p the model's preference probability.

- **`vopt_u` (I-optimal design).** Per head, the Laplace posterior covariance of the last layer is Sigma = (ridge I + sum over revealed judgments of the head of w phi phi')^-1 (ridge 1; a revealed judgment informs only its own head). The gain of candidate i is w_i / (1 + w_i phi_i' Sigma phi_i) x sum_j (phi_j' Sigma phi_i)^2, summed over the candidate judgments j of the same head: the decrease of the summed logit variance over the candidate pool if i is labelled (unit target weights). Greedy selection with rank-one updates of Sigma (so a batch is aware of its own redundancy). This is the linearised expected error reduction of the pool (cf. Direct Acquisition Optimization; Schein and Ungar's A-optimality for logistic regression).
- **`vopt_u_inf1`.** `vopt_u` with the gain multiplied by the predicted probability that the judgment is decisive (regularised logistic regression on type, pair distance and cosine, fitted on the outcomes revealed so far).
- **`fisher_dopt`** (Active Reward Modeling): greedy D-optimal Fisher design of the last layer; **`bald_decisive`**: BALD of the own head under the Laplace posterior x predicted P(decisive). Both from the earlier study.
- **`vopt_htr`**: `vopt_u` restricted to HTR candidates (the rest of the budget, if the HTR candidates run out, is filled with `vopt_u` on the other types); **`vopt_hw4`**: the gain of HTR candidates multiplied by 4 (priority weight); **`random_htr`**: random among HTR judgments (the allocation-only baseline).
- Tried and not better (development only): NTK I-optimal design (kernel over all head parameters incl. the shared first layer; its first-layer part is 1.3x the last-layer part), ridge in {0.3, 1, 3, 10}, sensitivity-weighted targets, A-optimality, type quotas, P(decisive) from anchor-head scores (`decisive_v2`), expected-gradient-length ideas.

## 3. Design of the evidence (what is confirmatory and what is not)

- Seeds 600-629 were the only seeds used for development (all exploration, choice of rule forms). Each confirmatory run used fresh seeds, was pre-registered in a committed file before running, and the analysis code was fixed (`new_methods_confirm.py`, `new_methods_confirm4.py`, `new_methods_final_tables.py`).
- 1: seeds 700-734, `vopt_u`, `vopt_u_inf1`; 6 tests (3 metrics), Holm 6. 2: seeds 800-834, 4 methods x {AUC, accuracy}, Holm 8. 3: cold start (`NM_INITIAL=random`), seeds 900-934, 4 methods x 3 metrics, Holm 12. 4: HTR-targeted, seeds 1000-1034, 2 methods x 3 HTR metrics x 2 baselines, Holm 12. 5: priority weight, seeds 1100-1134, 5 tests, Holm 5. 6: cross-world replication (train and test worlds image-disjoint), seeds 1200-1234, 4 methods x 3 metrics, Holm 12.
- Pre-registration 1 was the first confirmatory run and gave a weaker result than development: accuracy significant (+0.0095, +0.0114; Holm 0.0004, 0.0002), AUC positive but not significant after Holm (+0.0058, +0.0049; Holm 0.13, 0.18), log-loss not (+0.007, +0.005). The decision to add pre-registrations 2-5 followed from this and from post hoc robustness runs (cold start, old schedule); this is stated in each file.
- Seeds 700-719 were additionally used for two post hoc robustness runs (old head schedule; random initial set) after pre-registration 1; the cold-start result found there motivated pre-registration 3, which is why it was repeated on fresh seeds.
- Pooled estimates over several confirmatory sets are post hoc.

## 5. What the strategies pick, and what we learned about why

- The picks are **not** more decisive than random ones (decisive share 0.49-0.52 versus 0.51-0.52 at 60 judgments; tie 0.09-0.11 versus 0.13-0.15; not_apply 0.39-0.40 versus 0.34-0.35) but concentrate on fewer distinct pairs (37 versus 42) and shift the type mix (less (1x1) 0.18-0.20 versus 0.25, more sqrt13 0.33 versus 0.28).
- **Knowing whether a judgment will be decisive is worthless for this endpoint**: random selection among truly decisive judgments (perfect knowledge) is no better than Random (log-loss -0.01 to -0.09, AUC about 0 to +0.01, accuracy 0 to +0.015; Split A, seeds 600-604). Ties and not_apply judgments train the push-down and equality terms and are as useful. This explains why the P(decisive) factor adds nothing, and why asking only decisive questions would not help.
- **Oracle ceiling** (Split A, dev seeds 600-609): top-b judgments by hindsight single-addition test log-loss improvement beat Random by 0.16-0.20 log-loss and 0.04-0.05 accuracy; the practical rules recover about a third of the accuracy gap. The correlation between any observable feature (feature norm, leverage, p(1-p), expected gradient length, predicted or true decisiveness, anchor scores, unseen images, type) and the true utility of a single judgment is |rho| <= 0.06 on 8 seeds, so a learned per-candidate acquisition function (LAL) has nothing to learn from; the gains of the design rules come from batch-level geometry (coverage of the head's feature space).
- Type quotas, ridge, A- versus I-optimality, the NTK kernel and the outcome factors change the gain by less than the seed noise.

## 6. Caveats (read before using any number)

1. Same 168 pair groups in every seed; splits resample the same data (pre-registration 6 uses two image-disjoint halves, but both halves come from the same experiments and the head hyper-parameters were calibrated on all data). Whether the effect holds on genuinely new data (the lab's new growth data) is untested. The cold-start and priority results are conditional on this data set.
2. Test sets are small (about 54-63 decisive judgments; about 13-16 for HTR). HTR gains are therefore measured with large per-seed spread (sd 0.06-0.07 in accuracy) and need the 35-seed averages to be visible.
3. The head schedule matters (see summary); the schedule was calibrated on three seeds, one batch per seed and budget.
4. The pair-space rules of the earlier study (core-set, TypiClust, ProbCover, DPP, ...) were adapted to the judgment unit by my own decisions; other adaptations might change them. Relation-aware core-set is included only as a comparator.
5. Development numbers are optimistic: they are the best of several variants on the same 30 seeds (winner's curse); only the pre-registered sets are evidence.
6. `vopt_u` is not shown to be better than Fisher D-optimal or BALD x P(decisive); the family result is the claim.
7. Accuracy was not a primary endpoint of the original judgment-unit study; it is the pairwise metric reported by classifier2.

## 9. Using the rule on new data (sketch)
1. Cache the frozen SimCLR features of all images (`frozen_encoder_reward_head.FrozenFeatures`, `save_feature_cache`), including the new unlabelled ones.
2. Train the head on every judgment labelled so far plus the reference/bad-image anchors with the per-budget gentle schedule (`results/pair_endpoint_study/schedule_judgment_unit.json`, or lr 0.0003 / 100 steps, see pre-registration 7): `frozen.train_model(exp, features, [], lr, steps, rows=<DataFrame of labelled judgment rows>)`.
3. Build candidates: one dict per (image pair, type in {1x1, c6x2, sqrt13, HTR}) not yet labelled, with keys `pair_id` (unique judgment id), `base_pair`, `img1`, `img2`, `type_idx`; the already labelled judgments are passed as dicts with the same keys plus `outcomes=[(type_idx, was_decisive)]`.
4. `import new_methods_study` (registers the rules), then `picked = new_methods_strategies.NEW["vopt_u"](cands, labeled, model, cache, budget=10, seed=0)` (or `NEW["vopt_hw4"]` for the HTR priority); send the `picked` (pair, type) judgments to the labelling GUI, retrain with the returned labels and repeat in rounds of 10 (the sequential protocol).
5. For a prospective test keep a random arm: draw the same number of (pair, type) judgments uniformly from the same candidate list for the control group, evaluate both on a fixed held-out set of expert judgments.

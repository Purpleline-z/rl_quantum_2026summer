Hi Justin, update on the active selection results (changes since the Oct 6 numbers). Figures attached: (1) the old 8-strategy accuracy curve, (2) the new strategy-vs-random plot.

1. The old 8-strategy results (fig 1) were mostly noise. Run-to-run variation came from the order of the selected pairs and the fine-tuned encoder, the test set was only 28 images, and at budget 100 every strategy got the same 100 pairs (the pool was only 100). No code bug. The "best strategy per budget" didn't survive more seeds.
2. Fix: froze the SimCLR encoder, trained only the reward head in an order-independent way. Run-to-run s.d. went down to ~0.04.
3. Ideal-image type accuracy can't compare strategies: the ideal anchors alone already give 0.848, pair labels alone give 0.37–0.55, and a frozen 1-NN gets 0.871. So I switched the endpoint to held-out preference (log-loss / AUC on image-disjoint pair groups). This is the same thing as classifier2's pairwise holdout accuracy, just with two more metrics.
4. New comparison: 33 strategies (the original 8 + 17 from the literature, e.g. BADGE, TypiClust, Fisher D-optimal, Laplace-BALD, DPP, ProbCover + all-head versions) vs random, 35 seeds, one-shot and sequential rounds of 10, two splits (a small split, and a classifier2-style 80/20 split). See fig 2: filled = significant after Holm.
5. Result: no strategy is robustly better than random, gains are small (log-loss ~0.03–0.05, AUC <0.01). Which rule wins depends on the split: Laplace-BALD / BALD×P(decisive) on the small split (one-shot only), core-set on the classifier2 split. Uncertainty-based rules never beat random. Coverage rules tend to be better at the smallest budgets. This conflicts with the Oct 6 table (uncertainty best at budget 100, Cluster-Margin at 25, etc.).
6. A flaw in my earlier design: the labeling GUI asks one pair and one type per query, so the real query unit is one (pair, type) judgment. My simulation picked a whole pair group and revealed all its judgments (avg ~3.1), with the budget counted in groups. So "budget 10" was really ~31 judgments, and the other types came for free. This may have hidden differences between strategies.
7. Now rerunning everything with one judgment as the query unit and the budget in judgments (10/20/40/60). Will update you when it's done.
8. Code and results: https://github.com/Purpleline-z/rl_quantum_2026summer/tree/claude/frozen-encoder-strategies (report: code/ACADEMIC_REPORT_DRAFT.md §5.10–5.13).
9. Questions: (a) is held-out preference log-loss/AUC okay as the main endpoint? (b) if the rerun still shows no gain over random, is "just label randomly" an acceptable conclusion for the lab, or should we look at a different setup (e.g. larger pool, second encoder)?
